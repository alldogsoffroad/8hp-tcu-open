# 19 — Function catalog (full-firmware decompile sweep)

**Status: complete (2026-11-08).** Every code-bearing function in the stock firmware
(`1034420267_sh7254r.elf`, 10,982 Ghidra functions — 10,898 with code) is decompiled,
classified, named, and cataloged. The names are applied to the Ghidra project
(`~/opt/ghidra_projects/tcu_full`) as `USER_DEFINED` symbols; the catalog and data files
live in [`catalog/`](catalog/) (this directory was generated by the sweep tooling in
`~/tcu_sweep`, which holds the raw per-function decompiles).

## Conventions

- Names are `lower_snake_case` with module prefixes (`boot_ plant_ can_ spi_ sol_ shift_
  dtc_ meas_ tbl_ mon_ park_ ...`); duplicate names across entries carry `__2`, `__3` suffixes.
- The three pre-existing labels (`caseD_6/4/16`) were kept and documented in place.
- Kinds: `logic` (behavior), `library`, `stub`, `dispatch`, `data-accessor`, `irq`, `entry`,
  `init`, `unknown`. Catalog entries carry **[O]** (observable) / **[I]** (inferred)
  confidence markers per the project convention.
- Semantic anchors: the 201 spec-cited addresses (`known_map.csv` in the sweep tree) and
  cross-unit call-graph edges resolved during the sweep.

## Spec corrections and discoveries (selection)

- Spec 06's "SHA-1" label on the Auth_TSW hash is **RIPEMD-160** (unit 01; consistent with
  the spec 17 §5 forgery analysis).
- The boot-selection question (spec 06, "open") is decoded: the handover/self-test block at
  0x3D6E6–0x3EFC2 validates two flash images and honours a RAM-downloaded helper
  (magic 0x5AA5/0xA55A at 0xFFF80080) (unit 05).
- A **second instance of the spec 11 §3 shift-phase engine** exists at 0xE5E48–0xE7FEE,
  driven by task 0xDE0D8 (unit 30) — the spec documents only the 0x10F7D0 instance.
- Spec 14 §4.3's "second writer" open question: 0x000C79B8 writes the lever object
  0xFFF8304C+0x00 (unit 25).
- The calibration selector mapping (spec 09 §1.1) is extended with the exact
  group-pointer/source pairs 0xFFF84E7C–0xFFF84F64 (unit 39).
- Checksummed parameter records with record ids (0x1FD/0x108/0x11C/0x13A/0x112/0x1D0/0x155/
  0x1C7/0x1A7) not present in `1034420267_eeprom_records.csv` (units 22–24) — bench lead.
- 17-byte VIN-like identity buffers at 0xFFF82E14/0xFFF93BED exposed via DIDs 0x138F/0x1390
  (units 08, 44) — spec 15 candidate.
